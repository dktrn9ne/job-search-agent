# Tailoring System

## Resume Tailoring

Start from the master resume. Build role-specific versions by changing emphasis, not facts.

Allowed changes:

- Reorder bullets and sections.
- Rewrite summary to mirror the role's business need.
- Bring relevant projects, metrics, tools, and leadership examples forward.
- Add natural keywords from the job description when the underlying experience is real.
- Remove low-relevance content to make room for stronger proof.

Not allowed:

- Inventing employers, dates, roles, projects, metrics, tools, certifications, degrees, clearances, or responsibilities.
- Overstating ownership where the user contributed but did not lead.
- Claiming domain expertise not supported by the user's validated history.

## Cover Letter Tailoring

Use when required, requested, or strategically helpful.

Structure:

1. Direct opening naming the role and why it fits.
2. Two proof paragraphs mapping experience to the company's needs.
3. Short close with availability and enthusiasm.

Avoid generic admiration. Use company-specific signals only when verified from the posting, company site, product, public news, or user knowledge.

## Application Question Macros

Maintain macros for repeated questions:

- Why this company?
- Why this role?
- Tell us about yourself.
- Product or program leadership example.
- Cross-functional conflict example.
- AI/product strategy example.
- Customer insight example.
- Data-driven decision example.
- Failure or learning example.
- Salary expectations.
- Work authorization.
- Availability.

Every macro should include:

- Default answer.
- Short version.
- Long version.
- Facts used.
- Fields requiring user confirmation.

## File Naming

Use clear names:

- `company_role_resume_YYYY-MM-DD.md`
- `company_role_cover_letter_YYYY-MM-DD.md`
- `company_role_application_answers_YYYY-MM-DD.md`
